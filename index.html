Playing the Silences

Type a message, choose how the operator keys it, and follow it through the TEMPO decoding chain: an encoder that turns each Morse mark into a spike on a dot or dash line, a front end that timestamps the spikes, a trained network that decides what each silence between marks means, and a beam search with a character language model that turns those decisions into text. Everything runs in your browser, using the same code and fixed-point arithmetic as the five-board RP2040 decoder in the paper.

2

Encoder

The operator keys each letter as dots and dashes. A mark is a dot if it is held for less than 1.92 time units (Tu) and a dash otherwise; when a mark ends, a 1 ms spike fires on the dot line or the dash line. The fist adds timing jitter and lets each word drift faster or slower. Grey ticks show where each mark would end with perfect timing; the thin lines show how far the fist moved it. A red ring marks a channel error: a mark held so far off that it lands on the wrong line.

3

Front end

The front end sees only when each spike arrived and on which line. It estimates the time unit T̂u from the shortest intervals and measures each interval (a silence plus the mark after it) in those units. Every point is one gap, coloured by what it really is; the lines mark the nominal intervals at the fist's base speed, 2, 4, 6, 8 and 10 Tu, converted into T̂u units. 4 is ambiguous: a 1 Tu silence before a dash (● circle = next mark is a dot, ■ square = a dash) looks exactly like a 3 Tu silence before a dot. Jitter and drift blur everything else. Click a gap to follow it through the rest of the chain.
